# User Explorer — лабораторная работа №6

## Название и цель лабораторной работы

**Тема:** «Async, Promise, Fetch, REST API».

Я создал это учебное приложение, чтобы на практике освоить работу с асинхронным кодом в JavaScript, `fetch()`, `Promise`, `async/await`, а также получение данных из REST API. В проекте я реализовал загрузку списка пользователей, поиск по серверу, просмотр подробной информации и параллельную загрузку статистики.

## Используемые технологии

- HTML5;
- CSS3;
- JavaScript ES6+;
- Fetch API;
- Promise, `Promise.all()` и `async/await`.

Я не использовал сторонние библиотеки, фреймворки и API-ключи.

## API и Base URL

Я использовал бесплатный API [JSONPlaceholder](https://jsonplaceholder.typicode.com/).

**Base URL:** `https://jsonplaceholder.typicode.com`

## Что я реализовал

- Загрузку и отображение пользователей с полями имени, username, email и города.
- Поиск пользователя через GET-запрос на сервер по параметру `username`; если поле пустое, загружается полный список.
- Просмотр карточки пользователя отдельным запросом по его ID.
- Параллельную загрузку пользователей и публикаций через `Promise.all()` с выводом итоговой статистики.
- Состояния загрузки, понятные сообщения об ошибках и кнопку повторного запроса.
- Адаптивную верстку для компьютеров, планшетов и телефонов.

## Как запустить проект локально

1. Сохраняю файлы `index.html`, `style.css`, `script.js` и `README.md` в одной папке.
2. Запускаю локальный веб-сервер из этой папки. Например, если установлен Python, выполняю команду: `python -m http.server 8000`.
3. Открываю в браузере адрес `http://localhost:8000`.
4. Для успешных запросов к JSONPlaceholder нужен доступ к интернету.

Также можно открыть `index.html` напрямую в браузере, если настройки браузера позволяют выполнять сетевые запросы с локального файла.

## Как работает async/await и зачем проверять response.ok

Я использую `async` и `await`, чтобы ждать завершения HTTP-запросов без блокировки интерфейса. `fetch()` возвращает Promise, а затем я преобразую ответ в JSON через `response.json()`. Но важно помнить: HTTP-ошибка, например 404, не всегда означает, что `fetch()` завершился с ошибкой. Поэтому я обязательно проверяю `response.ok` и выбрасываю `throw new Error(...)`, чтобы показать пользователю понятное сообщение и не принять ошибку за корректные данные.
